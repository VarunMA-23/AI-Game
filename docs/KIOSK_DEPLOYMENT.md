# Kiosk Deployment — AI PC Showdown

Status: Phase 1 build shell, audited Phase 4 idle reset and staff overlay implemented, and offline checks include banned-claim scanning. Full kiosk launch and pilot hardening arrive in Phase 7.

## Build and verification commands

```bash
npm install
npm run check:offline
npm run typecheck
npm run lint
npm run build
npm run preview
```

`npm run build` runs the offline source check and strict typecheck before `vite build`.

## Offline source check

`scripts/check-offline.mjs` scans `src/`, `index.html`, `public/` and `stores/` for:

- Runtime `fetch(...)`.
- `XMLHttpRequest`.
- `sendBeacon(...)`.
- `new WebSocket(...)`.
- External `http://` or `https://` URLs in non-data source.
- Banned claim wording such as FPS, frame time, latency, speedup multiples, battery-life figures, percentage improvements and benchmark figures.

Allowed exceptions:

- Citation URLs in JSON and SVG data files are not runtime requests and are skipped by the URL rule.
- Service worker network behavior generated by `vite-plugin-pwa` is the offline cache mechanism and is not application fetch code.

## PWA precache

`vite.config.ts` configures `vite-plugin-pwa` with:

- `registerType: 'prompt'` so a service-worker update cannot swap assets mid-session.
- Manual registration in `src/main.tsx`.
- A local SVG icon only; no remote icon request.
- Precaching for JS, CSS, HTML, SVG, PNG, JPEG, WebP, WOFF, WOFF2, JSON and webmanifest files.

Fonts are bundled locally through `@fontsource/inter` and `@fontsource/space-grotesk`. There are no runtime font requests.

## Store selection

`src/data/kiosk.config.json` selects `storeId`, `mode` and `staffPin`. The app loads the bundled `stores/{storeId}/inventory.json` at boot; placeholder store files intentionally fail the readiness gate.
